## Interview questions

1. What does "stateless" mean for an HTTP API, and why does it matter for scaling? 
   1. Stateless means that each HTTP request must carry everything the server needs. The server does not maintain the context of previous requests. 
2. Why is PUT idempotent but POST isn't? Is DELETE idempotent if the second call returns 404?
   1. PUT updates an entry, POST adds entries. Updating a value twice to the save value does not change the state, adding 2 entries does. Delete in dempotenti if the second request return 404 - no change to the state happened.
3. 401 vs 403?
   1. 401 is Unauthorized; 403 is Forbidden. The difference is that 401 doesn't know who the requester is while 403 the requester is known.
4. When would you return 409 vs 422?
   1. 409 is returned when a valid request is received but it conflicts with the current state. An example is trying to add 2 username entries to a database that has a unique constraint in the username. 429 is returned when the user has made too many requests   
5. PUT vs PATCH?
   1. PUT replaces a resource entirely. PATCH changes a resource partially. 
6. A client gets a 500 and a 400. Which one should it retry, and why?
   1. 500;  500 means something went wrong in the server. Many reasons why that could have happened and a retry might not encounter the same issue. 400 is caused by a bad request. Without the user changing anything, the request is the same, so still bad.
